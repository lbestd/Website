# Галерея — описание функционала

## Что это

Веб-интерфейс для просмотра и управления фотографиями. Фотографии хранятся на диске в иерархической структуре папок до 3 уровней вложенности. Галерея отображает дерево этих папок в левом сайдбаре; клик по конечной папке открывает сетку превью.

---

## Структура файловой системы

```
/mnt/disk/photo_share/
├── ОПУБЛИКОВАНО/           # корень — сюда смотрит галерея
│   ├── Категория/
│   │   ├── Подкатегория/
│   │   │   └── Альбом/     # до 3 уровней (level 0, 1, 2)
│   │   └── ...
│   └── ...
├── cache/
│   ├── small/              # webp-превью 256px (быстрая сетка)
│   └── big/                # webp 1280px (просмотр)
└── trash/                  # «корзина» — удалённые не стираются насовсем
```

Файлы с `@` или `.` в пути, а также симлинки (`followlinks=False`) — игнорируются.

---

## URL-схема

| URL | Метод | Описание |
|-----|-------|----------|
| `/gallery` | GET | Главная страница — сайдбар с деревом каталогов |
| `/preview?urla=<path>` | GET | Сетка превью для конкретной папки |
| `/list?urla=<path/file>` | GET | Отдать изображение (генерирует кеш если нет) |
| `/list?urla=<path>&prev=yes` | GET | Отдать маленькое превью (256px) |
| `/list?urla=<path>&prev=orig` | GET | Отдать оригинал JPEG |
| `/list?urldel=<path/file>` | GET | Удалить / восстановить файл из корзины |

Все endpoint'ы требуют BasicAuth.

## Кеш дерева каталогов (`_gallery_cache`)

`os.walk` по большой структуре папок — дорогая операция. Поэтому результат кешируется в памяти.

### Как работает

1. При старте сервера `aiohttp` запускает фоновую задачу `gallery_cache_worker` (через `app.on_startup`).
2. Воркер немедленно строит кеш, затем обновляет его каждые **5 минут** (`asyncio.sleep(300)`).
3. `os.walk` запускается в `run_in_executor` — не блокирует event loop.
4. Хендлер `/gallery` читает `_gallery_cache` без ожидания. Если воркер ещё не успел (старт сервера) — строит кеш синхронно один раз.
5. При остановке сервера задача корректно отменяется (`app.on_cleanup`).

```
старт сервера
    └─► gallery_cache_worker()
            ├─► _build_dirdict_sync()  [в thread pool]  → _gallery_cache
            ├─► sleep 300s
            ├─► _build_dirdict_sync()  → _gallery_cache
            └─► ...
```

### Где код

- `app/forum/views.py` — `_build_dirdict_sync`, `_refresh_gallery_cache`, `gallery_cache_worker`, хендлер `gallery`
- `app/forum/routes.py` — `_start_gallery_worker`, `_stop_gallery_worker`, регистрация в `app.on_startup / on_cleanup`

## Кеш изображений (webp)

Генерируется лениво при первом обращении к `/list?urla=...`:

1. Если `cache/small/<path>.webp` уже есть — файл читается с диска.
2. Если нет — читается оригинал JPEG, применяется `ImageOps.exif_transpose` (автоповорот по EXIF), сохраняются два файла:
   - `cache/small/…webp` — превью, short side → 256px, quality 95
   - `cache/big/…webp` — 1280px, quality 97
3. Ответ отдаётся в `image/jpeg` (независимо от формата, так работает текущий код).

## Режим редактирования

В сайдбаре внизу есть чекбокс «Режим редактирования». Его состояние сохраняется в cookie `mode` на 7 дней. Функционал удаления доступен только в этом режиме (на уровне UI; API `/list?urldel=` работает независимо от cookie).

---

## Удаление / восстановление

`/list?urldel=<path/file>`:
- Если `cache/big/…webp` **существует** → файл перемещается в `trash/`, кеш-файлы удаляются.
- Если `cache/big/…webp` **не существует** (уже удалён) → файл восстанавливается из `trash/` обратно в оригинальное место.

То есть повторный `urldel` на тот же файл работает как toggle.

## Frontend (`templates/gallery.html`)

- Дерево каталогов строится на клиенте из JSON (`alldir = {{ dirlist|tojson }}`).
- Рекурсивная функция `renderList()` создаёт `<ul>/<li>` с вложенными подменю.
- Анимация раскрытия подменю — `slideUp/slideDown` на CSS-высоте.
- Ссылка на папку ведёт на `/preview?urla=<dir>`.
- Сайдбар адаптирован для мобильных (breakpoint 1024px): высота пунктов меняется с 30px до 130px.
